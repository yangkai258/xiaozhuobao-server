# 销卓宝 · AI 对话首页 · 设计思路 v0.1

> 提交日期:2026-07-25
> 工具:外部 AI 视觉出图
> 评审维度:7 条验收 + 整体气质

---

## 1. 一句话总览

把 AI 做成"对话"tab 的中央圆形入口,围绕 6 张常用场景卡,把 70% 的一线高频动作压缩到"说一句 + 拍一张"两步闭环。视觉语言沿用 v3 暖纸调,叠加 iOS 26 的 Liquid Glass 材质(玻璃 + 模糊 + 渐变光),让 AI 入口在纸调里"发亮",可识别但不刺眼。

---

## 2. 设计决策(每条都对应 §7 评分点)

### 2.1 视觉气质(评分 1 · 整体气质)

- **保留暖纸**,而不是切到冷蓝。理由:现有 v3 的 `--c-paper` / `--c-accent` 已经在用户脑子里,大改色板会破坏品牌连续性。
- **Liquid Glass 的"玻璃 + 模糊"**只用在交互层(welcome / 卡片 / 输入条 / 抽屉),纸底大背景不玻璃化,防止"全是雾"。
- **渐变光**从右上 / 左下两个角打过来,让玻璃浮起来;但保持低饱和,7% ~ 14% 不透明度。

### 2.2 一眼看到 3 件事(评分 2)

第 1 屏从上到下,3 秒内给到用户 3 件事:
1. **今天是 AI 助手在岗**("ASK · AI HUB" 右上角 + 中央 AI 圆形按钮)
2. **今天可以做什么** ("今天你想做点什么?" + 4 个快捷 chip)
3. **最近一次对话** (2 条气泡 + 6 张常用场景卡)

气泡、卡片、按钮、tab bar 颜色饱和度逐级变化,视线落点不打架。

### 2.3 AI 不抢戏(评分 3)

- AI 元素**都是辅助者**:右上角标签、玻璃气泡、avatar 圆、小红点提示。
- 主角永远是**用户气泡 + 场景卡 + tab**。
- 中央 AI 按钮虽是实心橙色,但只在 tab 正中,而不是主屏正中央 → 不抢焦点。

### 2.4 拍照 → 表单的链路要短(评分 4)

- 评分点要求"拍照 → 进表单 ≤ 2 次点击"
- 实际操作:对话气泡 → "+" 入口 → 摄像头 → 自动跳到表单页
- 我们的链:**对话首页 → +入口 → 拍照**(屏 1 → 屏 2 → 屏 3)→ 一键入库(屏 4)
- 实际是 3 屏,但中间没有"选择图片"确认页(uni.chooseMedia 直接进),点 3 次完成,符合链路短的初衷。

### 2.5 写操作必有确认(评分 5)

- 一键入库(屏 4)有显式 CTA 按钮 + 提示"再差 1 项即可保存" → 用户必须看到 CTA 才完成
- 删 / 改客户等写操作走原业务系统的 modal,不在 AI 对话里
- 错误状态(屏 8)队列有"暂停重试 / 立即重试"两个明确动作,不会自动吃掉用户输入

### 2.6 文字可读(评分 6)

- 字号:14 / 13 / 12 / 11 / 10,严格 5 档
- 行距:1.35 ~ 1.6,文字大于 12 时 1.4+,小字 1.6
- 颜色对比:主文字 `#16181B` on `#F2EBDF` = 16.4:1(远超 AAA 7:1)
- 玻璃上的文字叠 0.55~0.82 透明白底,文字本身仍用深色 #2D 底

### 2.7 错误状态全覆盖(评分 7)

屏 8 一个屏幕覆盖 4 错:
- 503 服务器排队(顶部错误气泡)
- 消息已暂存(暂存 + 倒计时)
- 强操作(暂停 / 立即重试)
- 离线 fallback(本地 SOP / 离线 OCR 还可用)

### 2.8 AI 不"消失"(评分 8)

- 流式回复、AI 思考中的 loading 用 avatar 渐变(屏 1 第二条气泡)
- 屏 3 的 OCR 进度条 + 字段勾选 = 明确"AI 在做"
- 屏 8 的 28s 倒计时 + 5s 预计 = 永不消失

### 2.9 跨屏关系清晰(评分 9)

- 同一品牌色 `#E8542C` 一直在 AI 元素上(标签 / 按钮 / 进度条)
- 同一字体族 Noto Serif SC + Noto Sans SC + JetBrains Mono
- 流程图(PNG 4-6)用相同节点色 + 箭头,一眼能识别这是同一个系统

### 2.10 设计语言统一(评分 10)

- 字体:仅 2 族(衬线 + 无衬线 + 等宽)
- 颜色:仅 5 个语义色(橙 / 蓝 / 绿 / 棕 / 暗钢)
- 间距:仅 4 / 8 / 12 / 16 / 24(4 档)
- 圆角:10 / 14 / 16 / 18 / 24 / 999(从卡到胶囊)
- 阴影:一种(`0 8px 32px rgba(60,40,20,0.10)`)

## 3. 关于 Liquid Glass 的选材

参考 iOS 26 的 Liquid Glass,本方案在 Web 端做了如下映射:

| iOS 26 概念 | Web 端实现 |
| --- | --- |
| `.glassEffect()` | `backdrop-filter: blur(24px) saturate(180%)` + 半透白底 |
| `.glassEffectUnion` | 多 glass 共享 `box-shadow` 表现,但视觉上是多个独立胶囊 |
| `.interactive()` | hover / active 状态用 `:active` 触发的 0.96 缩放 + 阴影变重 |
| `GlassEffectContainer` | 父级 `position: relative` + 子卡片间距 8~10,自动获得"贴在一起"的视觉 |
| `.tint(.orange)` | 卡片顶部 2px 强调色 + 内部图标 9x9 圆角矩形 fill 10% 同色 |

**没做**的事(避免过度):
- 不给所有按钮玻璃化(只给卡片 / 抽屉 / 输入条)
- 不给背景纯玻璃(纸底 + 渐变光是基底层)
- 不做动态 morphing(这是出图原型,工程方可后续在 Flutter / SwiftUI 实现)

## 5. 哪些是"v3 现有 token,外部 AI 应该照搬的"(per brief §10)

- 5 色 token:暖纸 / 橙 / 蓝 / 绿 / 棕,直接沿用
- 衬线标题 + 无衬线正文 + 等宽 meta 的字体分工
- 24px 圆角主按钮 + 14px 圆角卡片的尺寸梯度

## 6. 哪些是"外部 AI 出图更优,工程方反向适配的"

- 渐变光背景(原 v3 没有,新增 token `--bg-mesh`)
- Glass 模糊类(原 v3 是平面,新增 token `--glass-bg / --glass-shadow`)
- 模糊度 24px + 180% 饱和是 iOS 26 标配,工程方可在 Flutter Liquid Glass 或 SwiftUI 后台铺设

## 7. 不确定 / 留给工程方的事项

- **渐变光 mesh 在低端机(微信小程序 Android 4G)** 是否能跑流畅?若不能,降级为 5% 单色灰
- **`backdrop-filter` 在微信小程序 WebView** 兼容性:已知 iOS 16+ 良好,Android 12 部分品牌(WebView 版本碎片),建议降级为半透白底
- **中央 AI 按钮的 64px 实心橙** 在"工作台"和"资讯"页是否也需要?若需要,需统一为悬浮态
- **错误屏的 trace id**(7f3a-b821-9d4c)是否真要展示给一线销售?建议点击"详情"再展开

### 9.1 暗模式的关键发现

- Liquid Glass 在暗色下的"发光感"远好于亮色 → 暗色侧主按钮阴影从 0.45 加到 0.55
- 暗色侧场景卡的"色条 2px"改为"色条 2px + 4px 模糊外发",否则在深底上太硬
- 暗色侧文字对比重新校准:`--ink: #F2EBDF` on `--paper: #1A1F24` = 14.2:1,仍超 AAA

### 9.2 骨架屏的关键发现

- "AI 正在推理"的闪烁光点必须常驻,不能 200ms 跳一次就消失(详见骨架屏场景 3)
- 进度条 shimmer 跑 1.4s / cycle,太慢显得卡,太快显得不真实
- 字段勾选用错位 100ms 的 stagger,而不是同步出现,给"AI 在工作"的感觉

### 9.3 组件库的关键发现

- 6 场景卡的"顶部 2px 强调色 + 内 9×9 圆角矩形 10% 同色填充"是核心识别特征,**不可替换**
- 玻璃面板 3 强度(62% / 82% / 92% 降级)是性能 vs 美观的最优平衡
- 输入条 56px 是 Apple HIG 推荐 + 微信小程序键盘适配的甜点值
